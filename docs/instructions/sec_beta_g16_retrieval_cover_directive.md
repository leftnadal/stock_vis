## 절대 규칙 (요약 재확인)

- `git add -A` 금지 — 모든 커밋은 파일 명시.
- force-push 금지. 부분 실패 → 즉시 HALT, 재시도·임기응변 금지.
- 판정 기준(≥70% 접두, 잔여율 15%)의 사후 조정 금지 — 분포를 본 뒤 기준을 만지는 순간 HALT.
- 잔여율 ≤15% **충족/미충족의 최종 판정은 감독 세션 몫** — 실행 세션은 수치만 보고하고 자체 판정·후속 착수하지 않는다.

## Gate R1 — 소급 1: 사전존재 13건 해소 원인 규명 + 캐노니컬 베이스라인 확정

**목적:** 직전 세션에서 사전존재 13건이 "저절로" 해소된 채 4084/0이 나왔다. 원인이 ⒜ CN-repair 랜딩에 포함된 실수리인지 ⒝ Neo4j 기동이라는 환경 우연인지 미규명 상태 — 규명 없이는 베이스라인을 신뢰할 수 없다.

**절차 (전부 읽기 전용 측정):**

1. 직전 기록에서 해소 전 13건 테스트의 식별자 목록을 복원 (git log / 이전 스위트 로그).
2. 13건 각각의 테스트 코드를 열어 Neo4j 연결 의존 여부를 코드 레벨로 판별 (fixture·클라이언트 임포트·skip 마커).
3. 판별 보강: Neo4j를 내리지 **않고** 판단 가능하면 코드 판별로 종결. 코드만으로 불충분하면 — Neo4j 정지 → 13건만 재실행 → 재기동 순서로 실측. (라이브 자동화 시간대와 겹치지 않는지 확인 후 수행. 겹치면 코드 판별 결과만 보고하고 실측은 보류 명기.)
4. CN-repair 랜딩 커밋(68aeea28) diff에서 13건 관련 경로가 수정됐는지 교차 확인.

**분기:**

- **결과 A — 코드 수리로 해소 (환경 무관):** 캐노니컬 베이스라인 **4084 GREEN / 0 사전존재** 확정. `DECISIONS.md`에 확정 근거와 함께 등재.
- **결과 B — Neo4j-env 의존:** 베이스라인에 환경의존 주석 병기 형식으로 등재. 예: `4084/0 (Neo4j 기동 시) · 4071/13 (미기동 시, 사유: Neo4j-env 의존 13건)`.
- **결과 C — 혼합 또는 제3 원인:** HALT. 건별 내역 보고 후 정지.

## Gate G1.6 본문 — 기존 지시서 소비 (dry-run)

**`sec_beta_g16_partial_grade_directive.md`의 절차를 그대로 따른다. 본 커버는 아래 불변 조건만 재고정한다:**

1. **기준 선행 커밋:** partial_match 판정 기준(≥70% 접두 일치)은 분포 산출 **전에** 커밋된 상태여야 한다. Gate 0 통과가 곧 이 조건의 충족 증빙 — 보고서에 해시로 명시.
2. **정직한 등급 원칙:** partial_match는 접지 성공(verbatim)에 **합산 금지.** 4분포(v / n / nf / pm)는 상호배타·전수합 1751(명목).
3. **결정론 계약:** V-A 순수 계산 — **LLM 호출 0.** 분류 로직이 LLM을 요구하는 지점이 발견되면 즉시 HALT (계약 위반).
4. **병기 원칙:** 모든 비율은 명목(1751 기준)·유니크 기준 병기.
5. **산출:** ⑴ 재분류 후 4분포표 ⑵ 잔여 순수 not_found율(명목·유니크) ⑶ 분류 스크립트는 scratchpad 금지 — repo 커밋 (common-bugs #1).
6. **정합성 교차:** pm으로 전환된 건수가 G1.5 분해의 tail 발산 169(92.9%) 계열과 구조적으로 정합해야 한다. pm 건수가 169 계열 범위를 크게 벗어나면(±상식 범위 밖) HALT — 분류 로직 오류 가능성.

**이 세션이 하지 않는 것:** ≤15% 판정 선언 · Gate 2 착수(마이그 적용·실기록·flag-on·prompt v2 전부) · V-B 관련 어떤 준비 작업도.
