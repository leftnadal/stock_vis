# MON-JOURNAL-1 — 모니터 상세 일지 개편: 점수 차트 + 접힌 일지 (별건 · 모니터 트랙 소유 · 디렉터 초안 2026-09-04)

> 지위: **초안**. 결정·집행은 모니터(구 thesis) 트랙에서. 시각 계약 = docs/design/monitor_detail_ux.html §(b)+(c)
> (2026-09-04 사용자 확정). 발단 = 9/3 실화면 피드백: "일지가 화면 과점 · 매일 숫자 나열 대신 날짜×종합점수 그래프 하나".

## 문제 (실화면 근거)
- 일지가 일 1행 + 비서 코멘트 전문으로 세로 공간 과점(39일 관제 = 39+행) — 아래 섹션(매수 시나리오·이벤트)이 매몰.
- 점수 추이는 숫자 나열로는 읽기 어려움. "숫자 추이는 그래프가 전부 대체하나?"에 대한 답: **추이는 대체된다.**
  대체 안 되는 것 = 비서 서술 코멘트·이벤트 기록(관제 개시·시나리오 변경) → 마커 + 접힌 리스트로 남긴다.

## 제안 (목업 §(b)+(c) 그대로)
1. **점수 추이 차트** (일지 섹션 상단): x=날짜(관제 개시→오늘), y=종합점수. 단일 시리즈 2px 라인 · **0 기준선 점선** ·
   끝점 강조 + 현재값 라벨 · 비서 코멘트 있는 날 = 속빈 원 마커 · 관제 개시점 라벨. hover = 크로스헤어 + (날짜·점수·Δ·코멘트 첫 줄) 툴팁,
   마커 클릭 = 아래 일지 해당 날짜로 점프·펼침. 기간 토글: 2주 / 전체. 범례 불요(단일 시리즈 — 제목이 명명).
2. **일지 리스트 접기**: 기본 = 최근 3일. 이하 "이전 N건 ▸" 접힘. 비서 코멘트는 접힘 상태 한 줄 요약 → 클릭 전문.
3. **재료 실측 포인트(구현 세션 STEP 0)**: MonitorSnapshot 시계열(스냅샷 일 1회 여부·결측일 처리), 기존
   `snapshot_series.py`·`sparkline.py` 서비스 재사용 가능성(스파크라인 → 본 차트 승격), 일지 데이터 소스(점수 행 vs 비서 행 구분 필드).
4. 행위보존: 일지 데이터·저장 무변(표시 계층만). 기존 일지 전체 보기는 접힘 펼치기로 보존(정보 손실 0).

## 결정 포인트 (모니터 트랙 사이클에서)
- 결측일 표시(선 끊기 vs 보간) / 2주·전체 외 기간 프리셋 / 차트-일지 상호작용 범위(점프만 vs 하이라이트) / 모바일 폭 대응.

## 검증 제안
- 39일 실데이터(IONQ)로 렌더 스크린샷 vs 목업 대조 · 일지 접힘 후 페이지 세로 높이 전/후 측정(과점 해소 정량화).
