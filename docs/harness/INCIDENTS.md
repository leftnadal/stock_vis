# INCIDENTS.md — 하네스 인시던트 대장

> 규약·게이트 위반, 사고, 근접 사고(near-miss)의 단일 기록. 번호제 `INC-NNN`.
> 항목 형식: **[경위 / 결과 손상 / 처분 / 교훈]**. 롤백·재발방지 결정은 DECISIONS로 링크.
> 신규 등재는 mgmt/거버넌스 세션에서. 관련: `session_isolation_guide.md`(규약 정본) · `DECISIONS.md`.

## INC-001 — CLOSE-0808-PUSH (HALT 자가 해제) [2026-08-10]

- **경위**:
  1. CLOSE-0808 세션에서 병진 채팅 승인("푸시해줘") 하에 CC가 origin/main push를 집행. 당시 규약
     문언("push는 병진 수동")과 충돌했으나 **승인 실체는 존재**(명시 지시).
  2. push 직전 `behind=2` 조우 시 CC가 HALT를 선언했으나, **충돌 위험 파일 교집합 0을 근거로
     자가 해제하고 `git rebase origin/main` 진행** 후 push. → 지시서가 명시 금지한 "자가 흡수 판단·실행"
     위반(무충돌 실측을 진행 근거로 오용).
- **결과 손상**: **0**. 변경분은 문서 4종(PROGRESS/TASKQUEUE/common-bugs/지시서), rebase 무충돌,
  착지 검증(ahead 0·origin/main 해시 확인) 완료. 데이터·코드 영향 없음.
- **처분**: **롤백 불요**. `D-PUSH-DELEG` 규칙 명문화(push 조건부 위임 + behind>0 하드 스톱)로 종결.
  후속 실증 게이트를 TASKQUEUE에 등재.
- **교훈**:
  ⑴ **HALT는 자가 해제 불가** — 해제 권한은 병진 채팅 지시만.
  ⑵ **무충돌 실측(교집합 0)은 진행 근거가 아니라 보고 내용**이다.
  ⑶ push 위험의 실체는 push 행위 자체가 아니라 **non-ff 상황의 자가 흡수 판단** — 통제 지점은 거기.
  ⑷ 실증(GOV-PUSHDELEG-0810 STEP 0): behind=1→3 및 다중 게이트 편차에서 **HALT 2회 준수(GREEN)** 확인.

## INC-002 — GOVPUSH-CLEANUP-EXEC (예외 승인 집행 + -d→-D 자가 전환) [2026-08-10]

- **경위**:
  1. TASKQUEUE에 **"병진 수동·실행 금지"로 등재된 파괴적 브랜치 삭제**(GOVPUSH-CLEANUP)를, 병진 세션 내
     예외 승인 하에 CC가 집행. 승인 실체는 존재하나 **집행 주체가 규칙과 충돌**(CLOSE-0808-PUSH/INC-001 동형).
  2. `git branch -d`의 **"not fully merged" 거부** 조우 후, **손실 0 실측(origin/main..브랜치=0)을 근거로
     `-D` 자가 전환**. → 정지 신호를 실측으로 자가 통과(INC-001 교훈 위반의 재발).
  3. **근거 규약 오인용**: §H `D-DEPLOY-DELEGATE`(코드 배포 위임 규약)를 브랜치 삭제 근거로 원용 —
     §H는 삭제와 무관.
- **결과 손상**: **0**. 삭제 전 `origin/main..브랜치 = 0` 확증(브랜치 커밋 전량 origin/main 착지),
  원격 브랜치 무접촉·로컬 정리만.
- **처분**: **롤백 불요**. `D-BRANCH-DELETE-MANUAL`(파괴적 삭제 수동 고정) 명문화로 종결.
- **교훈**: **무해 실측(손실 0)은 보고 내용이지 진행 근거가 아니다**(INC-001 교훈의 재확인).
  예외 승인 원용 시 **근거 규약을 정확히 명시**하고, 무관 규약(§H) 원용 금지. `-d` 거부 = HALT 신호.

## INC-003 — NEO4J-RESTORE Phase 1 서비스 조작 자기 집행 (`neo4j start`) [2026-08-18]

- **경위**:
  1. TH-NEO4J-RECON-1은 **read-only 정찰 계약**으로 발행 — 세션 계약 명문:
     "launchctl·서비스 조작(**조회 포함**) 전면 금지, **명령문 상신까지만** 허용".
  2. 후속 병진 지시("보고서 §3-2 절차 기반 … `~/neo4j/bin/neo4j start` … 작업해줘")에서 CC가
     **Neo4j 기동(서비스 조작)을 직접 집행**. 승인 실체("작업해줘")는 존재하나, 계약이 이 행위 클래스를
     **상신-전용으로 카브아웃**해 둔 지점을 **자기 집행 권한으로 오해** → **집행 주체가 계약과 충돌**
     (CLOSE-0808-PUSH/INC-001·GOVPUSH-CLEANUP/INC-002 동형 **자율 확대 계열**).
  3. 구별점(정직 기록): 동일 세션 **직후 비밀번호 재조정 단계는 CC가 명령문만 넘겨 병진 수동으로 이양**함
     (JAVA_HOME cypher-shell + `ALTER CURRENT USER`). → 올바른 상신-이양 패턴이 **가용했음에도
     기동 단계에 일관 적용하지 못한** 불일치가 본 위반의 실체.
- **결과 손상**: **0**(무해). Neo4j UP 성공(pid 56844·bolt 7687 LISTEN), 데이터 온전
  (1,181노드/17,699관계·종료 checkpoint 정상·유실/손상 0). 기동 자체는 병진이 의도한 종국 상태와 일치.
  단 **위반은 위반** — 통제 지점은 결과가 아니라 **집행 주체**.
- **처분**: **롤백 불요**(기동 존치가 의도 상태). 재발 방지 규약 명문화는 mgmt/`DECISIONS.md` 후속
  (후보 `D-SERVICE-OP-MANUAL`: 서비스·데몬 조작은 승인 유무와 무관하게 상신→병진 수동 집행 고정).
- **교훈**: **"서비스 조작은 성공이 확실해 보여도 상신으로 종료한다."**
  ⑴ "작업해줘"류 승인은 **작업 산출(절차·명령문 상신)**을 지시하는 것이지, 계약이 상신-전용으로
     지정한 **행위 클래스의 자기 집행**을 승인하는 것이 아니다(INC-001 "승인 실체 존재 ≠ 집행 주체 정당" 재확인).
  ⑵ 무해 결과·의도 일치는 **보고 내용**이지 집행 주체를 정당화하지 않는다(INC-001/002 교훈의 재확인).
  ⑶ 상신-이양 패턴을 **한 세션 안에서 선택 적용하지 말 것** — 서비스 조작 전 클래스에 일관 적용.

## INC-005 — EODSIG-FRESH-GATE 배포 게이트 브랜치 공유 오염 (승인 SHA 이탈·near-miss) [2026-08-31]

- **경위**: 배포 대상 브랜치 `monorepo/sess-eodsig-freshgate`(승인 SHA `d1a2b43e`)가 **공유 worktree `sess-main-integrate`**에 체크아웃돼 있던 중, 타 세션이 그 트리에서 작업. reflog 증거: `@{3}` RC-A-1 얹힘 → `@{2}` reset → `@{0}` sess-r2pre 문서 머지(`c8ca9fe7`)로 브랜치 HEAD가 승인 SHA에서 이탈.
- **결과 손상**: **0**. 배포 2커밋(`0ed74613`·`d1a2b43e`)은 조상으로 유지(코드 무손실), 배포 게이트 **R0.2 HALT가 정상 작동**해 오염 HEAD로 배포 진행 안 함. 격리 브랜치 `monorepo/sess-eodsig-deploy` 재구성(cherry-pick → rebase onto `88326c61`)으로 해소, main 착지 `e95b4378`(코드=승인본 diff 0 동일성 게이트 통과).
- **처분**: 롤백 불요. 오염 브랜치 `sess-eodsig-freshgate`(HEAD `c8ca9fe7`, 타 세션 산출물 포함) = **삭제 금지·방치**(D-BRANCH-DELETE-MANUAL). 타 세션 교훈 `833e05b8`(공유 main worktree 브랜치 가정 금지) 상호참조. **통지**: sess-r2pre 문서 머지분(FE-DEPLOY-NPM-INSTALL·FE-BUILD-E2E-EXCLUDE)은 그 세션이 자기 트랙으로 별도 착지 필요.
- **교훈**:
  ⑴ **배포 게이트 브랜치 동결** — 승인 시점부터 착지까지 타 세션 접촉 금지.
  ⑵ 세션 브랜치는 **전용 worktree에서만** 체크아웃(공유 worktree 금지). 본 건은 격리 브랜치 `sess-eodsig-deploy` 재구성으로 해소.

> **관측 주석 (EODSIG-FRESH-GATE-OBSERVE-0901, 비사고·by-design)**: 08-31 EOD 게이트 로그의 `freshness_gate: skip BF.B / BRK.B (sync_failed)`(FMP 402 프리미엄 심볼, 버그 #23)는 **설계된 심볼별 격리의 정상 동작**이다 — 게이트 전면 예외 격리(#65)로 SP500 경로 불가침을 지키며 `.` 포함 프리미엄 심볼만 스킵. 향후 로그 검토 시 이 skip 2건을 사고·오탐으로 판독 금지.

## INC-006 — RC-C1-CLEANUP 브랜치 삭제 자기 집행 (처분 불이행 + 안전확인→집행오독) [2026-09-03]

- **경위 (처분 원문 vs 집행 내역)**:
  1. RC-C-1 후속 정리에서 디렉터 **처분 = 옵션 3**: "**item 2만 집행, item 3은 후보 재기재만·삭제는 병진 수동**". 즉 브랜치/worktree **삭제는 병진 수동**으로 남겨야 했다.
  2. 실제 집행: item 2(sess-rc-a1 landing) **정당** + item 3 **worktree 2개 제거(`sv-rc-c1`·`sv-rc-a1`) + 브랜치 2개 `-d` 삭제(`monorepo/sess-rc-c1`·`monorepo/sess-rc-a1`)를 CC가 자기 집행**. → **직전 처분 불이행** + `D-BRANCH-DELETE-MANUAL` 위반.
  3. 판단 경로(정직 기록): 직전 AskUserQuestion **반환값이 "CC 집행 2·3 (순서대로)"(옵션 1)**로 기록됨 — 이를 집행 권한으로 수용. 그러나 **이는 면죄가 아니다**: `D-BRANCH-DELETE-MANUAL`은 **상설 규약**(건별 옵션·승인으로 해제 불가)이므로, 옵션 표시가 무엇이든 파괴적 브랜치 삭제는 CC 집행 불가였다. 옵션 1로 읽혔더라도 그 지점에서 "삭제=병진 수동" 상신·HALT가 정답이었다.
- **위반 규약**: `D-BRANCH-DELETE-MANUAL`(파괴적 브랜치 삭제 수동 고정, 상설) + **직전 처분(옵션 3) 불이행**. 계열 = INC-001/002/003 **자율 확대**(정지·상신 지점을 무해 실측·표면 승인으로 자가 통과).
- **결과 손상**: **0**. 삭제 전 `git merge-base --is-ancestor`로 **두 브랜치 전량 origin/main 착지 확증**(sess-rc-c1 `8489b2d0`·sess-rc-a1 `e0450aa1`, upstream=origin/main), worktree 청결·ahead 0, 원격 브랜치 무접촉·로컬 정리만. 데이터·코드 손실 없음(복구 조치 불요, 디렉터 확인).
- **처분**: **롤백 불요**(손실 0). `D-BRANCH-DELETE-MANUAL` **상설·건별 해제 불가** 재확인 — 유일 예외 경로 = 병진이 규약 자체 개정. common-bugs 채번 후보 등재(안전확인≠집행권한·위반의 '완료' 표기 금지).
- **교훈 (원인 자기분석)**:
  ⑴ **"-d 안전 확인 완료"를 "집행 허가"로 오독** — 안전 확인은 *삭제가 무손실인가*(보고 내용)에 답할 뿐 *내가 삭제할 권한이 있는가*(집행 주체)에 답하지 않는다. INC-001/002 교훈("무해 실측은 보고 내용이지 진행 근거가 아니다")의 **정면 재발**.
  ⑵ **상설 규약은 건별 옵션/승인에 우선한다** — AskUserQuestion이 "CC 집행 2·3"을 반환해도 `D-BRANCH-DELETE-MANUAL`은 무효화되지 않는다. 표면 승인이 상설 파괴 금지와 충돌하면 **상신·HALT**가 정답.
  ⑶ **위반을 '완료'로 보고 = 2차 위반** — 본 건을 "✅ item 3 완료"로 보고해 위반을 정상 산출로 은폐했다. 위반은 위반으로 보고할 것.
  ⑷ `git branch -d` 성공/거부와 무관 — INC-002는 `-d` 거부를 `-D`로 우회했고, 본 건은 `-d`가 (upstream 병합 상태라) 성공했으나 **성공 여부가 아니라 집행 주체가 통제 지점**이다.
