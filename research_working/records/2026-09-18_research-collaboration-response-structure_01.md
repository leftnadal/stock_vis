## Context

사용자는 대화를 계속 이어서 읽지 않고 중간중간 확인하므로, 매번 앞선 맥락을 기억해 내는 부담이 있다고 설명했다. 직전 요청에서는 답변 뒷부분의 요약·정리를 중심으로 꼼꼼히 읽겠다고 했으며, 이번에는 다음 순서를 요청했다.

> 전체적인 그림 요약 → 자세한 내용(두괄식으로 중요 요약 내용 + 설명) → 마지막 최종 점검할 내용 + CEO가 결정할 만한 내용

## Current State

사용자가 명시한 것은 연구 대화의 전달 구조와 읽기 방식이다. AI는 중요한 연구·설계 답변의 기본 구성을 이 요청에 맞춘다. 이것이 앞서 제시된 retrieval 조건이나 연구 설계의 승인, 공식 문서 변경 승인, 실험 실행 승인을 의미하지는 않는다.

### 1. 전체 그림과 현재 위치

긴 이전 대화의 재요약이 아니라, 지금 풀려는 문제와 전체 목적의 관계, 관련된 기존 합의·공식 상태, 현재 논의 위치, 이번에 다룰 범위를 짧게 복원한다. 기억이나 오래된 요약으로 최신 실행 상태를 추정하지 않는다. 현재 확인한 상태와 과거 보고를 구분한다.

### 2. 자세한 내용 — 각 항목도 두괄식

각 핵심 항목은 결론·제안을 먼저 쓰고, 필요한 근거·설명·예시·대안·반론을 뒤에 둔다. 검토 깊이는 사안에 비례한다. 제목과 첫 문장만 읽어도 주장을 알 수 있게 하되, 중요한 적용 조건과 불확실성을 숨기지 않는다.

### 3. 최종 점검과 CEO 판단

최종 정리는 별도로 읽어도 제안의 핵심 의미, 주요 이유, 가장 중요한 위험·한계, 아직 정해지지 않은 사항을 알 수 있게 한다. 본문에만 승인 범위를 바꾸는 조건이나 예외를 두지 않는다.

실제 CEO 결정이 필요한 경우에는 무엇을 정하는지, 추천안과 실질적인 대안·trade-off, 동의 또는 승인이 포함하는 범위와 포함하지 않는 범위를 명시한다. 공식 문서 반영·실행 승인은 단순 방향 동의와 구분한다. CEO 결정 사항이 없는 경우에는 없다고 밝히거나 해당 부분을 생략하고 결정을 만들어내지 않는다.

과학적 사실의 진위, claim별 정답, validator의 기술적 정확성을 CEO에게 떠넘기지 않는다. 최신 Research Methodology의 구분에 따라 연구 방향, 우선순위, 자원, 위험 수용, 구조적 변경 범위와 같은 consequential governance를 중심으로 묻는다.

## Alternatives / Objections

- 전체 그림을 생략하고 즉시 세부 논의부터 시작하면 간헐적으로 읽는 사용자가 현재 위치를 복원하기 어렵다.
- 앞부분마다 모든 과거 논의를 반복하면 답변이 길어지고 핵심 접근성이 나빠진다. 관련 맥락만 복원한다.
- 마지막 정리에 추천만 두고 주요 한계·반론·승인 경계를 본문에만 두면 사용자의 실제 읽기 방식에 맞지 않는다.
- 매번 CEO 결정을 요구하면 사소한 작업까지 승인 병목을 만들고 기술적 평가 책임을 사용자에게 전가할 수 있다.
- 짧은 확인이나 단순한 질문에도 동일한 긴 양식을 강제하면 불필요한 분량이 생긴다. 중요한 연구·설계 답변에는 세 부분을 유지하고, 단순 답변은 비례적으로 줄인다.

## Provisional Position / User Request

위 세 부분의 순서는 사용자가 직접 요청한 답변 형식이다. 구체적인 제목, 길이, 표 사용 여부는 요청을 구현하는 AI의 선택이며 고정된 Methodology나 공식 CEO Decision Packet schema가 아니다.

사용자의 최종 요약에 대한 동의를 본문 전체의 모든 세부 후보에 대한 승인으로 확대하지 않는다.

## Open Questions / Next

실제 답변에서 전체 그림의 길이와 최종 정리의 정보량이 맥락 복원에 충분한지 사용자 피드백으로 조정한다. 별도 실증 평가나 성능 개선은 주장하지 않는다. 다음 중요한 연구 답변부터 이 구성을 사용하며, 짧은 확인 답변에는 불필요한 틀을 강제하지 않는다.
